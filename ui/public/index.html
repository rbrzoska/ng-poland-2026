Briefing

The library ships a new major version. Migrate 120 components to it.

The workspace is an Angular 22 app (120 feature components, ~216 source files). Its component library has just been upgraded: <app-pill> v2 has a different API, a new PillTonePipe exists, and every consumer still speaks v1 — the app does not compile.

  • disableTooltip → tooltip, with the opposite meaning: every value negated minimally (!isActive → isActive, count > 3 → !(count > 3));
  • variant → tone, values renamed (success→positive, warning→caution), also inside ?: expressions;
  • when the value comes from a field, it goes through the pillTone pipe — and PillTonePipe must be added to that component's imports in TypeScript;
  • label is gone: its value moves into the element content — self-closing tags get expanded, [label]="title" becomes {{ title }};
  • and nothing else changes — <app-card> has an input with the same name.

This is what ng update migrations do for Angular Material. Here we ask: who should do it in your own codebase — an AI agent, or the compiler with the agent's help?

The idea

The agent should not type out hundreds of edits. It should describe the change — and let the compiler apply it.

The tool

ng-facts migrate spec.json: an API change written as ~10 lines of JSON. The Angular compiler finds every element, the edits are mechanical. No AI output for the edits, no files read into the context.

Text search cannot tell it from the pill. Changing it breaks the card for every consumer you did not see.

Same prefix, different element<app-pill-legacy label="Legacy" [disableTooltip]="true" />

The old pill, still on the v1 API on purpose. <app-pill\b matches it; the compiler's selector matcher does not.

Same name, plain class field@if (disableTooltip) { … }

Each feature has its own field called disableTooltip. It is not the input. Nor is the comment, nor the hint text.

Six formatting styleslabel='Plain' · one attribute per line · /> on its own line · @for

Single quotes, double spaces, nested ?:, ?., [] and calls in expressions, two pills on one line — text is not structure.

A > inside an attribute[disableTooltip]="count > 3"

Ends a <app-pill[^>]*> regex in the middle of the tag; the rest of the element is never seen.

Values inside expressions[variant]="isActive ? 'success' : 'warning'"

Only the string literals change — the condition must stay untouched.

A field instead of a literal[variant]="statusVariant"

Cannot be mapped in the template: needs the pipe, and an edit in the component's TypeScript imports.

Input → content projection<app-pill label="X" /> → <app-pill>X</app-pill>

A structural change: the tag is expanded, the attribute removed (with its line), the end tag merged.

Inline and external templatestemplate: `…` · templateUrl

A quarter of the components keep the template inside a .ts string literal.

An external consumerinputs: { [name]: true }

The built app sets the card input by a name computed at runtime — only an API that did not change keeps it working.

Compiler + spec (execution only)

ng-facts migrate pill-v2.migration.json with a spec written beforehand: the API change as data, every edit applied mechanically by the Angular compiler. This is not a competitor of the agents — it is the part the agent with ng-facts delegates. Writing the spec costs the agent ~27 s; executing it costs the compiler ~0.15 s.

Agents run with Read/Edit/Write/Glob/Grep/Bash, no MCP servers, no user settings, a per-agent budget cap — and without the answer key or the ready-made spec.

  1. TypeScript ASTComponents, selectors, signal inputs and templates — inline literals with their exact offset, or templateUrl.
  2. parseTemplate()The Angular compiler's own parser: elements, bindings, @if/@for, expressions — all with exact source spans.
  3. SelectorMatcherEach element matched to its component the way the compiler does it: <app-pill> and <app-card> never mix.
  4. Expression ASTNegate by structure (PrefixNot, LiteralPrimitive, Binary); map string literals inside Conditional; anything else → pipe.
  5. Structural editsRemove an attribute (with its line), expand /> into content + end tag, add PillTonePipe to the decorator imports and the import statement.
  6. Spec in, edits outThe API change is ~10 lines of JSON. Dry run first; anything it cannot decide goes to a "needs a decision" list.

tool/ng-facts.mjs. The whole migration: ~2 680 edits in 170 files, 80 imports added, in ~130 ms — byte-identical to the answer key.

1 · The compiler

ngc --strictTemplates: v1 bindings on v2 are NG8002, a wrong value type is a type error. Before migration: 700 errors.

2 · The diff — twice

Every file aligned line by line with the answer key (correct, missed, wrong lines), and then the compiler's own template AST compared element by element: formatting-blind, meaning-exact. "Functionally correct" = 0 ngc errors and 0 elements wrong.

3 · The built app

ng build, served here. Every pill compared with the reference: text, tone and tooltip — a red frame marks a difference.

4 · The API contract

<app-pill [tooltip]="true"> must show a hint; an external consumer of <app-card> must keep working.

5 · The cost

For agents: time, turns, input tokens (incl. cache) and dollars, read live from the Claude CLI stream.
