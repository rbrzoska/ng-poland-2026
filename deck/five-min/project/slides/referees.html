A green build is not a correct build

Rename disableTooltip to tooltip and forget the negation: it compiles clean, and every tooltip in the app flips. So the compiler is the first referee, never the only one.

I

ngc --strictTemplates

A v1 binding on v2 is NG8002; a wrong value type is a type error.

II

AST diff vs answer key

Element by element with the compiler’s own AST: formatting-blind, meaning-exact.

III

The built app

ng build, then every pill compared with the reference: text, tone, tooltip.

IV

The API contract

An external consumer, input name computed at runtime, must keep working.

A migration can compile and still be wrong: a dropped negation type-checks. Four referees, the compiler first; the second one, the AST diff against the answer key, is what “functionally correct” means on the race slide.
